# 设计哲学

ovoice 的每一条架构决策都来自真实事故或明确的取舍。本文记录这些原则，供贡献者对照——改代码前先看这里是否被违反。

## 1. 历史即真相，视图即重建

会话历史是一份 **append-only JSONL**（`cache/history/YYYY-MM-DD.jsonl`），它是唯一真相源；发给 LLM 的 `messages` 每一轮都从盘上**重建**，从不跨轮持有。崩溃、重启、升级，最多丢"正在打字的半句"，不丢任何已落盘的状态。所有下游（上下文、前端重建、dream 整理、mem 检索）都读同一份历史，没有第二份状态。

## 2. 硬切优于压缩

上下文窗口控制不做"压缩历史"，而是 dream 推进 marker 的 `until_seq`，**硬切**：发送视图只包含 marker 之后的事件，之前的一概不读。压缩历史会让发送内容随实现细节漂移且不可复现；硬切的上下文永远可以从盘上精确推导。这与业界经验一致（context reset beats compaction）。

## 3. 记忆是蒸馏，不是存储

记忆管线的铁律：**原始记录永远完整落盘，压缩只发生在蒸馏层**。dream 把历史整理进四级漏斗（日段 → 月 → 年 → MEMORY.md 索引），蒸馏的输入必须是原文——任何在落盘层"顺手截断"的行为都是对记忆源头的污染。详见 [memory.md](memory.md)。

## 4. 结算要诚实

每个动作的终态必须让模型和用户知道**真实发生了什么**：

- 子代理失败 → 回传失败原因 + 死前的部分产出，绝不静默丢弃；
- 成功但空输出 → 字面量 `(无输出)`，绝不注入空正文；
- 截断 → 显式标记「已截断，可用 subagent status 查看」，绝不假装完整；
- 工具被打断 → 合成「用户中断，未执行」的 tool_result，不留悬空调用。

反面教训：曾因孤儿 tool_result 渲染硬编码「完成」，失败在模型眼里成了"完成 + 空正文"——不诚实比没有信息更糟。

## 5. 自愈不变量必须双向闭合

毒化输入（崩溃残留、模型畸形输出）靠发送视图的自愈层消化，但**配对/一致性不变量必须双向检查**。单向自愈曾留下暗洞：assistant 侧剥了孤儿 tool_call，tool 侧的孤儿消息却常驻——每次重建都触发 MiniMax 400 (2013) 死循环。规则：写下不变量时，同时写"正向不满足怎么办"和"反向不满足怎么办"。

## 6. 保险丝分层，兜底可调

失控保护分两层：**螺旋熔断**（连续同参同工具且无文本 → 强停）是主保险丝，抓病态死循环，与轮数无关；迭代上限（`max_tool_iters` / `subagent_max_iters`）只是对"缓慢漂移型失控"的兜底，因此给得宽（默认 5000）且可配置——数小时、数千轮的长任务是正常负载，不是异常。

## 7. 单写者，事件驱动

driver 是一个串行的事件循环（mpsc + `tokio::select!`），历史写入走单写 task，记忆文件只有 dream 一个写者。所有共享状态都是"单写多读"，从头消灭锁竞争与写冲突。并发能力放在正确的地方：子代理各自 tokio task + 独立取消令牌，后台作业独立进程。

## 8. 人机协同有超时

agent 该问就问（`ask_user`：候选项 + 自定义输入 + 倒计时），但**不无限等**：超时自动选推荐项自主推进。等待要有产物，中止要留痕迹，恢复要能继续——这是"常驻助手"与"一次性问答机"的区别。

## 9. 本地优先

会话、记忆、录音、任务库全部在本地目录；无遥测、无内嵌账号；密钥用户自备、只存本机 config。作为桌面助手，用户的对话数据是最私密的个人数据，架构上就不给它离开本机的路径。

## 10. 失败路径要有名字

每条错误路径都给一句明确的话，告诉模型或用户发生了什么、能做什么（重试 / 换措辞 / 查看完整产出）。裸错误码、空串、静默吞掉都是债务——它们会在最不可维护的时刻变成几小时的排查。

---

这些原则部分吸收了 [pi (earendil-works)](https://github.com/earendil-works/pi) 等 agent harness 的公开设计经验：显式状态机、结算诚实、有界视图 + 完整真身的分层。借鉴而非照搬——ovoice 的场景（常驻、语音、中文、单机）决定了自己的取舍。
