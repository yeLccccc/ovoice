## 一、用户原文（忠实保留）

> 我的希望，是提供一个 dream 命令，直接触发记忆整理过程，更新 MEMORY.md。你会检查发现待处理的 history 对话，然后**逐条对话进行归纳总结提取**，主题我感觉你可以**更加关注我用户的输入提示词**，以**一轮为基础单位**进行总结，然后再更新日概括，再更新月概括，再更新年概括，然后再根据我们预期的规则更新 MEMORY.md。

> 另外我希望你还能提供专门的工具：如 `mem ls 2026`，就列出当年所有月份以及对应月份的**月概括**；`mem ls 202607`，你就列出当月的所有**日概括**；`mem ls 20260731`，就列出当日的所有**对话主题概括以及具体的索引**；然后我希望你提供 `mem read xxx索引`，你能帮我**定位到具体的对话以及获取到具体的对话内容**。

## 二、结构化整理

### A. dream 命令（写端 —— 记忆整理）

1. 提供 `dream` 命令，直接触发记忆整理过程。
2. **检查并发现待处理**的 history 对话（自动定位到未整理的部分）。
3. 对待处理对话**逐条进行归纳总结提取**——是「归纳」，不是「复述」。
4. 归纳时**主题更关注用户的输入提示词**（user 的话为重心）。
5. 以**一轮（一个 user 回合）为基础单位**进行总结切段。
6. 整理后**逐级更新概括**：日概括 → 月概括 → 年概括。
7. 最后**按预期规则更新 `MEMORY.md`**。

### B. mem 浏览工具（读端 —— 逐层下钻 + 紧凑日期）

统一用**紧凑数字日期**，按位数自动判层级，逐层下钻：

| 命令 | 期望输出 |
|---|---|
| `mem ls 2026` | 列出当年**所有月份** + 每个月份的**月概括** |
| `mem ls 202607` | 列出当月的**所有日概括** |
| `mem ls 20260731` | 列出当日的**所有对话主题概括 + 具体索引** |
| `mem read <索引>` | 按**索引**定位到具体对话，并**获取该段对话的具体内容** |

---

## 三、关键语义点（后续对齐时重点确认）

- **「归纳」≠「复述」**：用户要的是提炼（产出/决策/结论），不是开头复述。
- **「关注用户输入提示词」**：主题与摘要应以 user 的表达为重心。
- **「一轮为基础单位」**：切段粒度 = 一个 user 回合。
- **紧凑日期 `YYYYMMDD`**：浏览工具期望用紧凑数字（非横线 `YYYY-MM-DD`、非空格分隔）。
- **`read <索引>` 直达原文**：期望按 evt 索引一步定位回原始对话内容，而非「先读日文件拿指针、再用 history --seq」两步。

---

## 四、接口简化原则（用户总诉求）

- **mem 只读命令**（`ls`/`read`/`history`/`search`/`index`）：用户认可「比较合理」，**保留，不再扩展**。
- **dream 简化为单一指令**：用户接口上**只有 `mem dream`**，不暴露复杂旗标。
  - 默认行为：一敲 = **LLM 归纳 + 整理全部待处理对话**（跑到空）。
  - `--mechanical` 降为**隐式 fallback**（config 无 api_key 时自动走机械），不作为用户可见选项。
  - `--once` / `--dry-run` 对用户不暴露（仅供内部 / agent 自动触发 / 调试用）。
  - 内部 `agent` 自动触发 dream 的逻辑（`dispatch_dream`）不受用户接口简化影响。
- 总原则：**做减法，不扩展太复杂。**

## 五、最终商定的 mem CLI 命令集（2026-07-31 收敛）

| 命令 | 职责 | 备注 |
|---|---|---|
| `mem dream` | 整理记忆（写端）；单一指令，默认 LLM 归纳 + 跑到空 | 旗标对用户不可见 |
| `mem ls <年/月/日>` | **列索引**：`2026`→各月+月概括；`202607`→各日+日概括；`20260731`→各主题+evt索引 | 重做，旧 ls 功能删除 |
| `mem read <年/月/日>` | **读整理后记忆内容**：`2026`→年主题；`202607`→日概括；`20260731`→事件段全文 | 读 dream 产物对应层级 |
| `mem history <日期> [--seq a..b]` | 读**原始对话**（dream 输入） | 读原文唯一入口 |
| `mem search <关键字> [--raw]` | 关键字搜索 | 保留 |
| ~~`mem index`~~ | — | **删除**（职责归 ls/read） |

### 关键决策

- **ls vs read 分工**：`ls` = 列索引（一行一条，轻，用来下钻）；`read` = 读内容全文（重）。
- **read 语义**：读 dream **整理后的记忆**（年/月/日层级内容），**不读原始对话**。
- **「read 索引直达原文」取消**：read 不做直达原文；回原文用 `history --seq`（`ls` 列索引时一并显示 seq 指针）。
- **日期格式**：紧凑（`20260731`）和横线（`2026-07-31`）两种都支持，自动判层。

## 六、MEMORY.md 结构 = 三层（2026-07-31 明确决策）

**期望 = `dream.rs` / `memory.rs` 的三层结构**（月/年内容全在 MEMORY.md，不拆树文件）：

```markdown
# 记忆索引（MEMORY.md）
## 日
- HH:MM evt-YYYYMMDD-NNN 标题              ← 今天每个事件一行
## 月
### 当月
- YYYY-MM-DD: 标题1；标题2                 ← 当月每天日概括
### 上月 {旧月}（冻结）
## 年
- YYYY-MM: {月主题}                        ← 每月一段月主题
```

**关键决策**：
- ✅ **采用 `dream.rs` 三层 MEMORY.md**（`## 日 / ## 月 / ## 年`），月/年内容全在 MEMORY.md。
- ❌ **`mem_dream.rs` 的两层设计偏离用户意图，需回退**：它把 MEMORY.md 砍成 `## 近期 + ## 年总览`，并用「四级漏斗」把月/年拆进 `memory/` 树文件（`memory/YYYY/YYYY.md`、`memory/YYYY/MM/YYYY-MM.md`）——这不是用户要的。
- `mem dream` 应产出**三层** MEMORY.md，对齐 `dream.rs`。
- **mem CLI 只读命令**（`mem_cli.rs`：`ls`/`read`/`history`/`search`）本来就配合三层 MEMORY.md，方向正确，不动。

## 七、最高原则与融合方向（2026-07-31 明确）

### ⭐ 最高原则：一个 MEMORY.md 包含一生的记忆

- MEMORY.md 是**一生的总记忆**：月主题 / 年主题**永久累积**在里面，**不随窗口滚出、不拆成独立文件**。
- spec 精神依据（`2026-07-30-mem-dream-design.md`）：line 16「可一生下钻」/ line 17「总结要有持久归处，不滚出」/ line 21「记忆永不遗忘」/ line 471「一生可下钻」。

### 四级漏斗整理逻辑 = 优秀，保留（重构核心价值）

- 年→月→日→对话的分级归纳，比 dream.rs 强。
- **整理大脑保留**：`split_rounds` / `mechanical_extract` / `reconcile_groups` / LLM 归纳 / 留尾 / 轮转。
- 用户原话：「四级漏斗设计是优秀设计，也是这次重构重要原因。」

### dream.rs 三层 MEMORY.md = 优秀呈现，采用

- MEMORY.md 三层：`## 日` / `## 月` / `## 年`，全在一个文件（月/年不拆出去）。
- 用户原话：「dream.rs 的 3 层是优秀的设计，年、月、日。」

### 融合方向（不是推倒精简，是从四级漏斗继承整理能力）

- 用户原话：「我希望本次重构是从前面四级漏斗拷贝整理而来，而不是让你完全精简的。」
- **保留**：四级漏斗的**整理逻辑**（mem_dream.rs 已有）。
- **改**：输出从「独立年/月文件 + MEMORY.md 两层入口（`## 近期/年总览`）」→「**全写进三层 MEMORY.md**（`## 日/月/年`，一生累积）」。
- = **四级漏斗的脑子 + 三层 MEMORY.md 的身子**。

### 对 spec 的修正

- spec line 19 / 472 的「**每级独立索引文件 + MEMORY.md 近期+年总览入口**」**被推翻**：不拆独立年/月文件，全进三层 MEMORY.md。
- 注意：mem_dream.rs 当前的「四级漏斗两层」是**照 spec 实现**的，非实现跑偏；是 spec 这个决策本身被用户修正。

### 待定张力（等用户确认）
