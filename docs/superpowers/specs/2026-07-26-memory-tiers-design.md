> **取代** `2026-07-26-context-management-design.md` 的 §7.8 step 2-4（晋级级联）与 §8（四层金字塔含周 / ISO 周）。

> 状态：**设计定稿，待 plan / 实现**（revise 仍延后）。

## 背景与为何修订

原 spec §8 设计了四层（日 / 周 / 月 / 年）+ §7.8 的晋级级联（跨午夜日→周、周 >7 天按 ISO 周概括→月、月 >3 月按日历月概括→年）+ §7.4 op3 revise。三个问题：

1. **ISO 周 + 日历月对齐需要 chrono**——本项目刻意回避 chrono（时间戳走 windows-sys `GetTimeZoneInformation` + 纯算术）。
2. **晋级级联 6 步表面积偏大**——spec §14 review 自己也标了"较大表面积、核心价值只靠日层成立"，建议分期降低推翻风险。
3. **周层冗余**——月层若装日级索引，"最近几天"已被当月逐日索引覆盖，周是多余的层。

本修订：**砍周、月层重定义为 2 月滚动窗口、月主题跨月 LLM、年 = 主题集合、全程无 chrono、结构规则全代码**。

## 铁律：结构规则全代码，LLM 只产内容

cadence（何时刷）、边界判定（跨月）、级联装配（下层 → 上层）、旧月退出——**全确定性代码**。LLM 只在两处产语义内容：**日提取** + **月主题**。规则不交给 agent 触发 → 稳定、可预测、可测。

## 三层（日 / 月 / 年）

| 层 | 内容 | 窗口 | 生成 | cadence |
|---|---|---|---|---|
| 日 | 每事件段：主题 + 时间 + 主语 + 详情 + `seq[a,b]` 指针 | 今天 | LLM 提取 | 每次 dream（有新对话） |
| 月 | **上月(冻结) + 当月(逐日追加)** 的日级索引 | ≤ 2 个月 | 机械（日概括 rollup） | 当月每日追加；跨月轮转 |
| 年 | 每个已完成月的月主题（一段话 / 月） | 历史已完成月 | 月主题 = LLM；装配 = 机械 | 跨月时 |

**周砍掉**：月层含日级索引，"最近几天"被当月逐日索引覆盖，周冗余。

### 月层细节

- **当月**：进行中，**逐日追加**（每天一条日概括；今天的行随事件累积更新）。
- **上月**：刚完成月的完整日级索引，**冻结**。
- **更早的月**：日级索引**退出月层**；其月主题已在年层；原始逐日在 `memory/{Y}/{M}/{date}.md` 可 drill。

### 月主题

- 一个**月完成**（跨月）时，LLM 从该月**全部日概括**综合**一段话**月主题 → 追加到年层。
- 每月一次 LLM 调用，可承受。

## 级联（自底向上）

```
日概括(每天) ──逐日追加──→ MEMORY「月」当月
                            │
        ┌─── 跨月(当月完成) ────┤
        ↓                      ↓
  当月→上月(冻结)        LLM 综合该月全部日概括 → 月主题(一段话)
  旧上月→退出月层                    │
                                     ↓
                            MEMORY「年」(月主题集合，每月一条)
```

日概括一身二用：既是月层的索引条目，又是月主题的合成原料。

## dream 一次 run（全自动维护）

```
0. [触发] idle ≥ dream_idle_secs(默认 600s) 或 cap ≥ dream_cap_turns(默认 50) user 事件（现有，不动）；单飞。
1. 段 [a,b] 非空？→ LLM 提取日 → append day 文件 + 当月日索引追加(今日行)   ← 日层
2. 跨月检查（本月 YYYY-MM > 月层"已建成月"）？
     是 → LLM 综合刚完成月的全部日概括 → 月主题 → 追加年层
        → 月层轮转：旧上月退出、刚完成月→上月(冻结)、新月→当月(空)
3. 写 dream marker（until_seq=b，现有）→ context 清空 + 注入「[记忆整理中，请忽略]」
```

每次 dream 跑 step 2 的跨月检查，**跨月才动月主题 / 年**；不跨只动日。全自动、用户零操作。

## MEMORY.md 最终形态（三节，全有界）

```
## 日    今天的事件（per-event，detail）           ← 每次 dream
## 月    上月(冻结) + 当月(逐日追加) 的日级索引    ← 每日 / 跨月轮转
## 年    每个已完成月的月主题（一段话 / 月）        ← 每月一条
```

三节天然有界（日 = 今天 / 月 ≤ 2 月 / 年 = 一行每月，历史月只留主题）。**无限涨的只有 `memory/{Y}/{M}/{date}.md` 文件树**（真相、永不删、可 drill）。

`ensure_memory_skeleton` 的四层骨架（日 / 周 / 月 / 年）改为**三层（日 / 月 / 年）**。

## mem CLI（drill 链不变 + 新增读 MEMORY.md）

- **现有 `ls` / `read` / `history` / `search` 不变**（drill 年 → 月 → 日 → 对话；文件树即索引）。
- **新增 `mem index [层]`**：读 MEMORY.md 的日 / 月 / 年节，返回给 agent（脱离 pinned 窗口时取摘要）。不传参 = 全部三层。

## 实现约束

- **无 chrono**：跨月 = `YYYY-MM` 字符串比对；"最近 2 月" = 月份算术。`civil_from_days` 已有。
- **状态**：月层"已建成月"标记（小 meta 文件 `memory/.dream-meta.json` 或 MEMORY.md 注释行），dream 读写、用户不碰。
- **day 文件 append-only 永不删**（真相之源）。
- **MEM 索引路径**：`memory/` + `history/` 现已归 `cache_dir`（见 `618b20c` workspace/cache 分离）；本设计在 cache_dir 内运作，不动 workspace。

## 不做（仍延后）

- **revise（修正）**：新事件与既有记忆矛盾时重写 MEMORY 条目（记忆再巩固）。"矛盾检测"难做对，延后。
- **ISO 周 / 日历月对齐晋级**：被本修订取代，**不要**重新引入。
